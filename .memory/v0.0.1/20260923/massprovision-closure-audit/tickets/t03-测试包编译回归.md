# t03 测试包编译回归（接口加方法的代价）

**状态**：✅ 已完成（backend）

**问题**：2026-09-22 批量签发给 `devicecert.Store` 加了 `GetByNodeID`，但**测试替身没跟着走** ⇒
`go test ./src/...` **直接 build failed**（不是"少一条用例"）：
- `src/rmneo/shadow/cmd/shadowd/main_test.go`：`failingStore`
- `src/rmneo/ca/signer/server_test.go`：`failingStore`、`invisibleStore`
- `src/rmneo/ca/signer/batch_test.go`：`failAfter`

⇒ 那一批记录的"门禁全绿"是**分范围复跑**的结论；全仓门禁当时是红的。

**实现**：四个替身各补一个方法（`failingStore`/`invisibleStore` 返回 `(nil, nil)` 或错误，`failAfter` 转发内层），
并在注释里写明"接口加方法时测试替身属于编译期门禁的一部分"。

**验证**：`go build ./...` exit 0；`go vet ./src/...` 不再报 `missing method GetByNodeID`；
`go test ./src/... -count=1` 无 FAIL（本轮复跑）。

**教训（写进设计 §8.7.4）**：给接口加方法后**必须跑整仓门禁**，只跑改动包看不见这类回归。
