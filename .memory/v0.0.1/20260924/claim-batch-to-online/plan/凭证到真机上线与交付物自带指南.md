# 计划：把一批签发凭证做到真机上线，并让交付物自带产线指南

来源：用户直接要求（2026-09-24）——"尝试将 `claim-batch-B-20260923-192813` 这个签发的证书
应用到串口连接的开发板上并验证上线云平台；告诉我经过了哪些流程；**以后在产物 claim-batch 目录
增加这个流程步骤操作指南，能够指导产线人员**"。

## 目标

1. 用真板（Korvo-2/COM12）把 `KORVO2-0000` 这份证书烧进去，验证它**以这份身份**上线到云平台。
2. 把"从交付物到上线"的流程与判据说清楚（可复跑、有证据）。
3. **让每一批交付物自带产线指南**（不是再写一篇文档站页面）。

## 步骤

| # | 步骤 | 产物 / 判据 |
| --- | --- | --- |
| 1 | 摸清平台侧：哪台监听器信任签发这批证书的 CA | `openssl s_client` 对每个 mTLS 端口跑一遍；`oneye-platca` = 平台 CA = 宿主 **18886** |
| 2 | 出可烧写镜像 | `mkcreds -zip <交付物> -out <目录>` ⇒ `creds.bin` 16384 B + 清单 |
| 3 | 固件对齐端点 | 量产预设 + 端口 18886；台面验证另开 Wi-Fi 文件（量产置 n） |
| 4 | 烧写 + 回读 | `provision-device.ps1` 退出码 0 + 回读逐字节一致 |
| 5 | 上线判据 | 串口 `link up … node=KORVO2-0000`、`esp.cred_source=partition`；门卫 `Client(KORVO2-0000, username=KORVO2-0000)` |
| 6 | 平台应答 | shadowd 日志 `caps/down`（授时）+ `log/down` ack |
| 7 | 让交付物自带指南 | 新包 `src/claim/batchguide` + 写入 ZIP 的 `README.md` + `tools/batchguide` 补发工具 + 契约/验收登记 |
| 8 | 顺手修掉"写了不生效"的配置 | 预设端口 18885→18886；dev defaults 的 `LOG_MAXIMUM_LEVEL_INFO` |

## 边界（这次不做）

- **不修**设备侧 `shadow/up` 没发出来（问题 3）与 `caps/up` 的 `model_version` 类型漂移（问题 4）：
  两者都已定位并登记，但都在 SDK/契约面，属下一轮；本轮只保证"证书把它带上平台"这件事被证明，
  并把"控制台看不到"的原因说清楚（不能含糊成"上线了"）。
- 不改平台 broker 拓扑（本轮用部署侧 `EMQX_URL` 指向平台 CA 那台作为临时接线）。
