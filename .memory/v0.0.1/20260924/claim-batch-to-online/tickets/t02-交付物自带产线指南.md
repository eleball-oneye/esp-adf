# t02 交付物自带产线操作指南（用户第 ③ 条要求）

**状态**：✅ 完成

## 为什么这么做（而不是再写一篇文档站页面）

用户要的是"**在产物 claim-batch 目录**增加这个流程步骤操作指南，能够指导产线人员"。
产线拿到的是一个 ZIP（常被解压转存到 U 盘/共享盘），操作它的人未必有权限翻文档仓；
而指南里的这几步恰好是在**写入设备唯一身份**——靠口口相传的代价是两台设备抢同一个身份
（上线互相踢线、事后无法分辨），或者一台机器永远上不了网。

## 指南里写的是**本批的实际参数**（不是通用模板）

批号、可灌注台数与逐台 `SN`/`serial`/到期、**签发这批的 CA 名**（从证书 Issuer 解析，不查表）、
**设备该连的 mTLS 端点**、`creds` 分区偏移与大小；再加五步操作与判据、五条红线、常见失败表。

端点走 `BATCH_GUIDE_CLOUD_ENDPOINT`（缺省 `mqtt.oneye.me:18886`）：它是**部署事实**而不是签发事实，
写死一个地址，换个环境就会出现"证书是好的、却连不上"——正是本轮踩到的那个坑。

## 单测（`src/claim/batchguide/batchguide_test.go`）

- 本批参数齐（批号/SN/serial/CA 名/端点/偏移/判据/红线）；
- 围栏渲染（raw string 不能含反引号 ⇒ `{{F}}` 占位替换）后**不留占位符**；
- `already_issued` 的设备**不进**"可灌注"表（否则产线会去找一个不存在的镜像）；
- 端点可被环境变量覆盖，且**多处出现一致**（只改一处会自相矛盾）；
- 无已签发证书 / 无批号 / 空 batch_id 都有兜底文案；
- 证书坏掉（非 PEM / nil）不 panic、不编造 CA 名。

## 踩到的两个自身错误（记下来免得重犯）

1. 指南模板一开始写成**一个 raw string 里嵌 `+"```"+`**，Go 直接编译不过
   （`raw string 不能包含反引号`）⇒ 改成 `{{F}}` 占位 + 生成时 `ReplaceAll`。
2. 测试里造"由某 CA 签发"的证书时，只给叶子模板填 `Issuer` 是**没用的**：
   `x509.CreateCertificate` 会用**父证书的 Subject** 覆写 Issuer（自签时就是自己）
   ⇒ "取签发者 CN"永远取到设备名，测试测不出东西。必须真造一张父证书来签。
