# t03 量产预设端口修正：18885 → 18886

**状态**：✅ 完成

## 问题

`sdkconfig.defaults.production` 把云端端点钉在 `mqtt.oneye.me:18885`，而 18885 是宿主上的
`oneye-crl` 容器（`cacertfile = /home/ubuntu/mtls-test/certs/ca.crt`，**另一台老 CA**）。
**申领服务签发的设备证书挂在平台 CA（`oneye-iot-device-ca`）下**，只有 `oneye-platca`
（宿主端口 **18886**，`cacertfile = platca-bed/ca.crt` = 平台 CA）认它。

实测（拿本批真证书跑 `openssl s_client -cert/-key/-CAfile`）：

| 端口 | 结果 |
| --- | --- |
| 18886（oneye-platca） | `CONNECTION ESTABLISHED` / TLSv1.3 / **`Verification: OK`** |
| 18885（oneye-crl） | `verify error:num=19:self-signed certificate in certificate chain` |
| 18884（oneye-mtls） | 同上 |
| 8883（oneye-emqx） | 同上 |

## 为什么危险

串口上的表现是 **TLS 握手被拒**，与"证书坏了"长得一样；而端口是**编译期**钉死的
（`CONFIG_ONEYE_FW_CLOUD_PORT` → `base_cfg.cloud_port`），选错只能重烧整批固件。
`oneye-platca` 的证书里 SAN 已含 `DNS:mqtt.oneye.me`，所以域名侧不用改。

## 改了什么

- `examples/oneye/korvo2_oneye/sdkconfig.defaults.production`：`18885` → **`18886`**，
  并把"端口必须与**信任签发 CA 的那台监听器**一致"、实测对照、以及"选错只能重烧"写进注释。
- 台面验证另有一份带 Wi-Fi 文件开关的构建（`output/.build/korvo2_oneye-platca18886/`）：
  量产预设把 `ONEYE_FW_ENABLE_WIFI_FILE` 置 n，台面上板子拿不到 Wi-Fi 就**直接跳过上云**
  （串口"未找到 Wi-Fi 凭据 → 跳过上云"），看起来像"连不上云"。

## 证据

- 门禁：`python tools/check-sdkconfig-defaults.py --sdkconfig <纯量产预设构建>/sdkconfig \
  --require sdkconfig.defaults.production` ⇒ **`[ OK ] sdkconfig.defaults.production：11 项全部存在且已生效`**，
  且构建出的 sdkconfig 里 `CONFIG_ONEYE_FW_CLOUD_PORT=18886`。
- 真机：串口 `cloud endpoint mqtt.oneye.me:18886 → OK` + `link up: mqtt.oneye.me:18886 … node=KORVO2-0000`。

## 仍未做

生产形态应当"**一台 broker、两个监听器**"（平台 CA 的 mTLS 监听 + 内部明文监听），
而不是像现在这样四台实验期容器并存、还要靠端口区分证书链。换环境时这里必须重钉 + 重烧。
