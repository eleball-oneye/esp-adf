# t05 平台侧接线与两个**未修**的缺陷登记

**状态**：⚠️ 部分完成（接线已修；两个设备/契约面缺陷已定位并登记，本轮不修）

## 已修：shadowd 与设备曾被接在**不同 broker** 上

CVM 上有一组实验期 broker：`oneye-emqx`（宿主 1883/8883）、`oneye-mtls`(18884)、
`oneye-crl`(18885)、`oneye-platca`(18886)。shadowd 原本订阅 `tcp://127.0.0.1:1883`
（= `oneye-emqx`），而平台 CA 的设备连的是 `oneye-platca` ⇒ **平台永远看不到这台设备**，
看起来像"设备没上线"。

处置：`/etc/oneye/shadowd.env` 的 `EMQX_URL` 指到 `oneye-platca` 的 docker 网桥地址
（`172.18.0.x:1883`，实测可达、`authentication=[]` 匿名可连），重启后日志
`mqtt connected to tcp://172.18.0.6:1883`。原文件已备份为 `shadowd.env.bak-*`。

⚠️ 网桥 IP 会随容器重建而变 —— 生产形态应是"一台 broker 两个监听器"，见 t03 末段。

## 未修 ①：设备根本没发 `shadow/up`

- 固件在自检块里调了 `oneye_dev_base_report_state(shadow)`（含 `esp.cred_source`），
  串口也打印了"凭据来源已上报：esp.cred_source=partition"；
- 但 broker 上**一帧 `shadow/up` 都没有**：把该设备的全部 `raw_bin_received` 十六进制
  解出来查 `shadow`（`736861646f77`）= **0 次**；实际只看到 `caps/up`、`log/up`、`status/up`(LWT)。
- 后果（这才是"控制台看不到设备"的根因）：没有影子文档 ⇒
  `GET /v1/devices/<SN>/shadow` = **404**、**身份视图为空**、注册表不建行
  （自动注册挂在 `shadow/up` 的消费端，见 `shadowd/main.go` 的 `mqttface.Subscribe`）。
- 为什么难查：`oneye_dev_base_report_state()` 的返回值在固件侧被 **`(void)` 吞掉**，
  成功与失败在串口上长得一模一样 —— 属"看不清"的一类缺陷。
- 已确认**不是**平台侧问题：shadowd 确实订阅了 `rmng/dev/+/shadow/up`
  （`emqx ctl subscriptions list` 可见），且它同时正常处理了同一台设备的 `caps/up`（授时）与 `log/up`（ack）。
- 下一步：先把返回值暴露出来（别 `(void)`，失败要打日志），再看是
  `bint_guard_link()`（要求 `initialized && started && connected`）、发送队列、还是 payload 构造失败。

## 未修 ②：`caps/up` 的 `model_version` 类型漂移

shadowd 明确报：

```
WARN drop caps/up on rmng/dev/KORVO2-0000/caps/up: data 不是 CapsUpData:
json: cannot unmarshal string into Go struct field CapsUpData.model_version of type int
```

设备发**字符串**、服务端要**整数** ⇒ 整帧被判无效丢弃（授时那半边不受影响，仍回了 `caps/down`）。
二选一改齐 + 在契约里加一条断言即可；不修则 `caps/up` 这条面一直是"看起来在跑、其实被丢"。

## 证据入口

- 门卫：`docker exec oneye-platca emqx ctl clients list` ⇒ 见 `Client(KORVO2-0000, username=KORVO2-0000, connected=true)`
- 订阅：`emqx ctl subscriptions list | grep shadowd`（6 条，含 `rmng/dev/+/shadow/up`）
- 平台应答：shadowd 日志 `time_sync → rmng/dev/KORVO2-0000/caps/down`、`ack → …/log/down`
- 未发证据：`docker logs oneye-platca | grep 'clientid: KORVO2-0000' | grep raw_bin_received | grep -c 736861646f77` ⇒ **0**
